# Заявки в Telegram

Форма сохраняет `Lead` и по одной записи `TelegramDelivery` для каждого получателя в одной транзакции SQLite. Ответ посетителю не зависит от доступности Telegram. Личные сообщения отправляет отдельный процесс; бот не принимает заявки от произвольных пользователей Telegram.

## Настройка

В защищённом `.env` на сервере:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_CHAT_IDS=ваш_числовой_chat_id,chat_id_директора
```

Оба получателя должны сначала открыть бота и нажать Start. Для личной переписки нужны числовые chat ID, а не @username. Повторяющиеся ID исключаются. Старый `TELEGRAM_CHAT_ID` поддерживается, если новый список пуст. Получатели задаются только на сервере; форма не может их изменить. Токен нельзя сохранять в Git или выводить в лог.

Без списка получателей заявки остаются в базе, но не создают очередь отправки. После настройки старые заявки автоматически не рассылаются. Это предотвращает неожиданную отправку исторических данных.

## Запуск

Перед выпуском: резервная копия SQLite и обычная проверка diff. Для существующей базы применить управляемую миграцию:

```bash
flask --app wsgi.py db upgrade
flask --app wsgi.py telegram-worker
```

В Docker обработчик включается явно:

```bash
docker compose --profile telegram up -d telegram-worker
```

Миграции необходимо применить до запуска обновлённого веб-процесса и обработчика. `--once` обрабатывает входящие кнопки и одну ожидающую отправку и завершает процесс; без флага обработчик опрашивает очередь каждые 5 секунд. Миграции добавляют таблицу доставки, желаемую дату занятия, поля обработки заявки и идентификаторы сообщений.

## Доставка и контроль

В админке: «Заявки» хранит обращения; «Доставка заявок» показывает получателя, число попыток, время успешной отправки, следующую попытку и безопасный код ошибки. Удаление заявок из стандартной админки отключено, чтобы не оставлять очередь без заявки.

Сбой одного адресата не мешает другому. Ошибки повторяются с увеличивающимся интервалом до часа. Успешно отправленные записи пропускаются. Атомарная пятиминутная блокировка записи предотвращает одновременную отправку двумя обработчиками и освобождается после падения процесса.

Telegram не предоставляет ключ идемпотентности для sendMessage: если сообщение принято, но ответ потерян или процесс упал до фиксации успеха, повтор может дать дубликат. Одинаковый номер заявки в обоих сообщениях помогает его распознать. Очередь не обещает доставку при блокировке бота получателем; ошибка остаётся видна в админке.

Все 28 форм проверены реальными отправками с локального сайта: заявки сохранены, уведомления доставлены. Данные явно помечены тестовыми. Production-деплой не выполнялся.

Документация API: https://core.telegram.org/bots/api#sendmessage

## Карточка и обработка

Название программы или страницы берётся из базы вместо технического URL. Не заполненные необязательные поля скрыты. Телефон размечен как phone_number; «Открыть контакт» отправляет штатную карточку контакта Telegram.

«Обработана» сохраняет статус, время и ID обработавшего получателя. Сообщение меняет заголовок и отметку кнопки; при нескольких получателях обновляются все сохранённые копии. Повторное нажатие не меняет время обработки. При ошибке редактирование повторяется. Кнопки доступны только настроенному получателю в его личном чате и проверяются по сохранённому ID сообщения.

Запускайте ровно один telegram-worker на токен бота: он получает callback через getUpdates, хранит offset в SQLite. Активный webhook не отключается автоматически — worker откажется запускаться. Старые сообщения без сохранённых message_id автоматически не обновляются. При потере ответа Telegram возможен повтор карточки контакта.
